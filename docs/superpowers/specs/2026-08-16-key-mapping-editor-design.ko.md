# 키 매핑 편집 화면 재설계

작성일: 2026-08-16

## 목표

버튼 편집 기능을 쉽게 찾고 편하게 사용하도록 개선하고, 검증된 매핑을 연결된 컨트롤러에 안전하게 저장한다. 매핑 버튼을 선택하면 현재 프로그램 창 안에서 전체 너비 편집 화면으로 전환한다. 편집 화면은 실제 키보드 입력, 크게 표시되는 분류별 키 선택, `Ctrl+C` 같은 값을 위한 명확한 자유 입력칸을 제공한다.

## 현재 문제

preview.23 키 선택기는 너비 240픽셀인 고정 우측 패널에 들어가 있다. 분류별 키 목록이 자유 입력칸을 화면 아래로 밀어내고 각 키 버튼도 지나치게 작다. 또한 현재 프로그램에는 실제 키보드 입력을 캡처하는 처리가 없으며 기존 텍스트 상자는 일반적인 문자열 편집만 지원한다. 이 때문에 키 조합 입력 기능을 찾기 어렵고 실제 사용 흐름도 완성되지 않았다.

## 선택한 화면 흐름

`MainWindow` 안에서 다음 두 화면 상태를 사용한다.

1. 매핑 전체 화면: 프로필 제어, 기기 이미지, 연결선, 모든 매핑을 보여준다.
2. 매핑 편집 화면: 매핑 값 버튼을 선택하면 해당 Micro 버튼의 전체 너비 편집 화면으로 전환한다.

편집 화면은 위에서부터 다음 순서로 구성한다.

- 뒤로가기 명령과 선택한 Micro 버튼 이름
- 눈에 잘 띄는 실제 키보드 입력 영역
- 분류 탭과 큰 키 선택 버튼 목록
- 항상 보이는 자유 입력칸
- 취소 및 적용 명령

적용하면 선택한 매핑을 변경하고 로컬 프로필에 저장한 뒤 전체 화면으로 돌아간다. 취소하면 매핑을 변경하지 않고 돌아간다. 별도의 기기에 저장 명령은 전체 활성 매핑을 검증하고 사용자의 확인을 받은 후 실제 기기 쓰기를 수행한다.

## 실제 키보드 입력 규칙

실제 키보드 입력 영역을 누르면 키보드 포커스를 받는다. 현재 누른 보조키와 주 키를 조합해 정규화된 매핑 문자열을 만든다.

- `C` 입력은 `C`가 된다.
- Ctrl을 누른 채 C를 입력하면 `Ctrl+C`가 된다.
- Ctrl과 Shift를 누른 채 S를 입력하면 `Ctrl+Shift+S`가 된다.
- 보조키 순서는 항상 `Ctrl`, `Alt`, `Shift`, `Win`, 주 키 순서다.
- Esc는 정상적인 매핑 키이며 `Esc`로 입력된다. 입력 취소로 사용하지 않는다.
- `Ctrl+Esc`, `Alt+Esc` 조합도 입력할 수 있다.
- `Ctrl` 같은 보조키 단독 매핑은 분류별 키 목록과 자유 입력칸에서 선택할 수 있다.
- 보조키가 아닌 키가 눌리면 캡처가 완료된다. 결과는 자유 입력칸에 들어가지만 적용 버튼을 누르기 전까지 저장하지 않는다.
- 취소는 화면의 취소 버튼 또는 뒤로가기만 사용한다.

## 구성 요소

`MainWindow.xaml`은 두 화면 상태를 표시하고 실제 키 입력 영역에서 발생한 WPF 미리보기 키 이벤트를 전달한다. 키 조합 문자열을 직접 만들지는 않는다.

`MainViewModel`은 편집 화면 열림 여부, 선택한 매핑, 임시 입력값, 키 분류 선택, 취소 및 적용 동작을 관리한다.

작은 키 조합 변환기가 WPF 키와 보조키 정보를 프로그램의 기존 매핑 문자열로 변환한다. 변환 로직을 분리해 실제 키 입력 결과를 일관되게 만들고 단위 테스트할 수 있게 한다.

프로토콜 프로젝트는 HID usage 인코딩, CRC 계산 및 저장 패킷 생성을 담당한다. 기기에서 읽은 스냅샷과 활성 매핑을 받아 검증된 패킷 시퀀스 또는 구체적인 미지원 입력 오류를 반환한다. BLE 전송 계층은 생성된 시퀀스를 보내고 응답만 수집한다.

## 데이터 흐름

1. 사용자가 전체 화면에서 매핑 값 버튼을 선택한다.
2. 뷰 모델이 현재 값을 임시 입력값으로 복사하고 편집 화면을 연다.
3. 분류별 키 선택, 실제 키보드 입력 또는 자유 입력은 임시 값만 변경한다.
4. 적용하면 임시 값을 선택한 행과 로컬 프로필 저장소에 기록하고 편집 화면을 닫는다.
5. 취소 또는 뒤로가기는 임시 값을 버리고 편집 화면을 닫는다.

## 안전한 기기 저장

현재 활성화된 기기 저장 프로필에 읽기-수정-쓰기-재읽기 흐름을 사용한다.

1. Micro 기기 하나가 연결되어 있고 매핑 스냅샷이 정상적으로 해석된 상태인지 확인한다.
2. 쓰기 직전에 45바이트 설정 페이지 네 개를 다시 읽는다.
3. 수정하지 않은 180바이트 payload를 저장소 밖의 타임스탬프 로컬 백업 파일로 보관한다.
4. 지원되는 모든 매핑을 확인된 4바이트 버튼 슬롯에 인코딩한다. 미해석 바이트, 프로필 메타데이터 및 아직 해석하지 못한 필드는 읽은 그대로 보존한다.
5. 각 45바이트 페이지에 polynomial `0xA001`, 초깃값 `0xFFFF`인 CRC-16/ANSI를 계산한다. CRC 하위 바이트와 상위 바이트 순서로 `04 01` 패킷에 기록한다.
6. 변경되는 Micro 버튼 요약을 보여주고 확인을 받은 뒤 생성한 페이지 쓰기 네 개와 관찰된 공식 commit 시퀀스를 전송한다.
7. 설정 페이지 네 개를 다시 읽고 쓰려던 각 슬롯의 HID 값과 비교한다.
8. 재읽기 결과가 모두 일치할 때만 성공으로 표시한다. 값 불일치 또는 시간 초과가 발생하면 백업을 유지하고 별도의 원본 설정 복구 명령을 제공하며 자동으로 복구하지 않는다.

이번 버전은 현재 활성화된 기기 저장 프로필 하나만 쓴다. 프로필 이름 쓰기와 기기 안의 추가 프로필 선택·생성은 관련 프로토콜 필드를 해석할 때까지 지원하지 않는다.

## 오류 처리

- 선택된 매핑이 없거나 임시 입력값이 비어 있으면 적용 버튼을 비활성화한다.
- 지원하지 않거나 식별할 수 없는 실제 키는 기존 임시 값을 덮어쓰지 않는다.
- 키를 길게 누를 때 발생하는 반복 KeyDown 이벤트는 무시한다.
- 로컬 프로필 저장에 실패하면 기존 상태 메시지 경로로 알리고 임시 값이 사라지지 않도록 편집 화면을 유지한다.
- 기기가 연결되지 않았거나 완전한 기기 스냅샷이 없거나 인코딩할 수 없는 매핑이 하나라도 있으면 기기에 저장을 비활성화한다.
- 지원하지 않는 자유 입력값과 HID usage 네 개를 초과하는 조합은 패킷을 보내기 전에 목록으로 보여준다.
- BLE 실패 또는 재읽기 불일치를 성공으로 표시하지 않으며 쓰기 전 백업을 삭제하지 않는다.
- 원본 복구는 두 번째 명시적 확인을 요구하고 복구 후 기기를 다시 읽어 값을 검증한다.

## 언어와 화면 배치

새 문구는 기존 `UiText`의 한글 및 영어 리소스에 모두 추가한다. `Ctrl+C`, `Esc`, `Page Up` 같은 키 매핑 값은 언어에 영향을 받지 않는 공통 문자열로 유지한다.

편집 화면은 최소 키 버튼 크기를 안정적으로 유지하며 공간에 따라 줄바꿈한다. 일반 지원 창 크기에서 카드 안에 카드를 넣거나 세로 스크롤에 의존하지 않는다. 창이 좁아지면 글자를 줄이는 대신 분류 제어와 키 목록을 다음 줄로 배치한다.

## 테스트 전략

- 뷰 모델 테스트에서 편집 화면 열기, 취소, 적용, 임시 값 보존을 확인한다.
- 키 조합 변환기 테스트에서 단일 키, 보조키 순서, `Ctrl+C`, `Ctrl+Shift+S`, `Esc`, `Ctrl+Esc`를 확인한다.
- 뷰 수준 테스트 또는 XAML 검사 테스트로 전체 편집 화면에 실제 키 입력 영역과 자유 입력칸이 존재하고 기존 240픽셀 편집 패널이 제거됐는지 확인한다.
- HID 인코더 테스트에서 선택 가능한 모든 키 분류를 확인하고 미지원 값은 패킷을 만들지 않고 거부하는지 검사한다.
- CRC fixture 테스트에서 공식 저장 페이지에서 관찰한 `D33A`, `8E09`, `CF30` 값을 재현한다.
- 패킷 생성기 테스트에서 스냅샷의 미해석 바이트는 유지되고 확인된 매핑 슬롯과 페이지 CRC 바이트만 변경되는지 검사한다.
- 뷰 모델과 가짜 전송 계층 테스트에서 저장 확인, 미연결 상태, 일부 쓰기 실패, 재읽기 성공, 재읽기 불일치, 백업 유지 및 명시적 복구를 확인한다.
- 복구 가능한 매핑 하나를 실제 기기에 저장하고 MicroKey Studio에서 재읽은 뒤 공식 모바일 앱에서도 독립적으로 확인한다.
- 기존 프로필, 프로토콜, 언어 및 기기 읽기 테스트가 모두 통과해야 한다.
- preview.24 패키지를 만들기 전에 WPF 전체 빌드와 휴대용 게시가 성공해야 한다.

## 제외 범위

- 기기 프로필 이름 해석
- 기기에 저장된 추가 프로필 생성, 삭제, 이름 변경 또는 선택
- Mac 전용 키 이름 및 동작
- 매크로 순서, 지연시간이 포함된 키 입력 또는 마우스 동작
