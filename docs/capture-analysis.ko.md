# 정제한 프로토콜 분석

이 문서는 현재 기기 저장 및 복원 preview에 필요한 검증된 구현 사실만 기록합니다.

## Write Page 무결성

- generated write page의 길이는 62바이트입니다.
- CRC는 초기값 `0xFFFF`, 반사 다항식 `0xA001`을 사용하는 CRC-16입니다.
- CRC 계산 범위는 45바이트 page payload인 바이트 17-61(포함)입니다.
- CRC는 바이트 7-8에 little-endian 순서, 즉 낮은 바이트부터 높은 바이트 순으로 저장합니다.
- 바이트 13-16의 page offset도 little-endian입니다.

## 저장 및 복원 안전성

- 저장은 먼저 연결된 기기에서 활성 설정을 읽습니다. 이 baseline에서 선택한 매핑 바이트만 변경하는 read-modify-write 방식이므로 나머지 모든 바이트를 보존합니다.
- baseline은 사용자가 저장을 확인하기 전에 `Documents/MicroKeyStudio/backups`에 백업합니다.
- 저장이나 복원 뒤에는 전체 설정을 다시 읽습니다. 읽기가 불완전하거나 요청한 매핑이 다르면 저장 성공으로 처리하지 않습니다. 복원은 전체 다시 읽기 결과가 백업과 바이트 단위로 같아야 합니다.

## 현재 제한과 검증 범위

- 프로토콜은 연결된 기기의 활성 설정만 지원합니다. 기기 쪽 프로필 이름과 프로필 선택은 아직 해석되지 않았습니다.
- 자동화 테스트는 패킷 구성, 바이트 보존, 백업 순서, 모의 전체 다시 읽기 처리를 검증합니다. 하드웨어 저장 및 복원은 독립적으로 검증되지 않았으며, 실제 기기 검증은 Task 9에서 진행할 예정입니다.
